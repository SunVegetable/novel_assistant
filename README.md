# 短剧创作助手（LangGraph 综合实践 · 短剧版）

教材 7.4 小说助手的短剧化改造。目标产能：**竖屏短剧 90 集 × 每集 2-3 分钟（约 700-900 字台本），每集有爽点、集尾有钩子**。

## 流程与图的对应关系

```
用户输入需求 → LLM生成[剧名/角色/核心冲突] → ⏸人工审核 ─┬─通过→ 两级大纲(总纲+幕表 → 逐集爽点/钩子) → ⏸人工审核 ─┬─通过→ 单集生成 ⇄自循环跑满全部集 → END
                    ^                          │                ^                                   │        (每集过一次检查点)
                    └────不通过：打回重生成──────┘                └────不通过：重排全部分集爽点─────────┘
```

## "每集都有爽点"是怎么保证的

爽点不靠写正文时即兴发挥，三层机制：

1. **设定层**：强制四类功能人设——逆袭主角 / 欠打脸反派 / 势利眼配角 / 情感线助攻
2. **大纲层**：两级排布。先排幕（幕=节奏单位，幕末必有大爽点），再逐集排「标题/剧情/爽点/钩子」，
   爽点类型强制轮换（打脸/身份揭晓/实力碾压/危机反杀/情感爆发/夺回失去的…），**不允许出现纯铺垫集**
3. **正文层**：单集提示词把该集的爽点+钩子作为硬约束喂进去——后段必须爆发指定爽点，最后一句必须停在指定钩子上；
   同时带上上一集的钩子和剧情，保证环环相扣

## 产能参数（环境变量可覆盖）

| 参数 | 默认 | 说明 |
|---|---|---|
| `TOTAL_EPISODES` | 90 | 总集数 |
| `EPISODES_PER_ACT` | 15 | 每幕集数（90集=6幕） |
| `EPISODE_BEATS_CHUNK` | 5 | 分集大纲每块行数——一次要15行模型会漏行，分块+短块重试 |
| `WORDS_PER_EPISODE` | 700-900 | 单集字数（1分钟≈300字台本） |

```bash
# 小规模试跑（6集，约3分钟）
TOTAL_EPISODES=6 EPISODES_PER_ACT=3 python3 main.py
# 全量生产（默认90集；约100次调用，预计20-40分钟）
python3 main.py
```

## 踩过的坑（解析相关，都已修复）

1. **模型吞分隔符**：输出 `剧情：...。爽点：xxx｜钩子：xxx`，爽点前的｜被吞——
   解析器改为按"标记词："出现顺序切片，不依赖｜是否存在
2. **模型漏行**：要 3 集只给 1 集——分集大纲分块生成（每块5行）+ 块内行数不足自动重试一次
3. **qwen3 思考模式**：必须 `enable_thinking: False`，否则思考 token 吃光 max_tokens、content 为空

## 中断机制设计（教材 7.4.8 深度思考）

- **为什么用 interrupt 而不是节点里 `input()` 阻塞**：`input()` 挂起的是进程，状态只在调用栈里；
  interrupt 是把"执行到哪了"写进 checkpointer 再停，状态可序列化、可恢复、可审计
- **多用户企业级**：每任务独立 `thread_id`，checkpointer 换持久化实现（Postgres/Redis），
  恢复时带同一 `thread_id` 调 `invoke(None)` 从断点继续。`main.py` 的恢复循环就是单机版
- **90集长跑的容错**：单集生成走图级自循环而非节点内 for 循环——每集完成过一次检查点，
  跑到第N集 Ctrl-C，同 thread 重跑从第N+1集继续，不重复花钱
